# 优化日志输出 - 共识文档

## 明确的需求描述

### 核心目标

优化日志输出，减少冗余日志，提升日志可读性。

### 具体需求

1. **调整日志级别**：
   - 将一些 DEBUG 级别的日志改为 INFO
   - 将一些 INFO 级别的日志改为 DEBUG
   - 确保日志级别使用合理

2. **合并重复日志**：
   - 合并连续的相似日志
   - 合并重复的状态日志
   - 合并相关的错误日志

3. **改进日志信息**：
   - 添加上下文信息
   - 改进错误日志
   - 使用一致的格式

4. **优化重试日志**：
   - 每次重试记录 DEBUG
   - 最后一次失败记录 WARNING

5. **采用标准模式**：
   - 记录主要步骤和重要状态
   - 不记录过于详细的调试信息
   - 不遗漏关键信息

## 技术实现方案

### 日志级别调整标准

- **DEBUG**: 详细的调试信息
  - 详细的参数值
  - 内部状态变化
  - 重试过程中的中间状态
  - 每个请求头的添加

- **INFO**: 关键流程信息
  - 程序启动和退出
  - 用户操作（输入链接、选择模式等）
  - 关键步骤的开始和结束（如"开始下载视频"、"视频下载完成"）
  - 重要状态变化（如"浏览器实例创建成功"、"Cookie 获取成功"）

- **WARNING**: 潜在问题
  - 重试失败（但最终成功）
  - 可选功能不可用（如直播名称获取失败）
  - 使用默认值的情况

- **ERROR**: 错误信息
  - 操作失败（如下载失败、Cookie 获取失败）
  - 最终重试失败
  - 异常情况

### 日志合并策略

1. **合并连续的相似日志**：
   - 将多个"已添加 XXX 请求头"合并为一条"已添加请求头：Cookie, User-Agent, Referer"
   - 将多个"获取到 m3u8 链接"合并为一条"获取到 N 个 m3u8 链接"

2. **合并重复的状态日志**：
   - 只在关键步骤记录状态，避免在循环中重复记录
   - 使用计数器记录循环次数

3. **合并错误日志**：
   - 将相关的错误信息合并为一条日志，包含所有必要的上下文

### 日志信息改进标准

1. **添加上下文信息**：
   - 在日志中包含相关的参数值（如 URL、文件名、路径等）
   - 在日志中包含操作的对象（如浏览器类型、保存模式等）
   - 在日志中包含操作的结果（如成功/失败、数量等）

2. **改进错误日志**：
   - 包含错误发生的步骤
   - 包含错误的原因
   - 包含相关的参数值
   - 包含可能的解决建议（如果适用）

3. **使用一致的格式**：
   - 使用统一的动词（如"开始"、"完成"、"失败"）
   - 使用一致的命名（如"视频"、"文件"、"链接"）

### 重试日志记录策略

- 每次重试记录 DEBUG：`第 N 次尝试未获取到 m3u8 链接，重试中`
- 最后一次失败记录 WARNING：`经过 N 次重试后仍未获取到 m3u8 链接`
