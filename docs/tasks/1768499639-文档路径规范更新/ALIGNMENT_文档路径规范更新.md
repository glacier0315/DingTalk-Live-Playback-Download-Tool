# 文档路径规范更新 - 对齐文档

## 一、项目特性规范

### 1.1 项目概述

钉钉直播回放下载工具是一个基于 Python 的桌面应用程序,用于从钉钉直播回放分享链接下载视频文件。项目采用模块化架构设计,遵循严格的开发规范。

### 1.2 项目结构

```
DingTalk-Live-Playback-Download-Tool/
├── src/                                    # 源代码目录
├── tests/                                  # 测试代码目录
├── assets/                                 # 静态资源目录
│   ├── bin/                                # 外部二进制程序目录
│   │   ├── N_m3u8DL-RE.exe                 # N_m3u8DL-RE可执行文件(Windows)
│   │   ├── N_m3u8DL-RE                     # N_m3u8DL-RE可执行文件(Linux/macOS)
│   │   ├── ffmpeg.exe                      # FFmpeg可执行文件(Windows)
│   │   └── ffmpeg                          # FFmpeg可执行文件(Linux/macOS)
│   ├── template/                           # 模板文件目录
│   │   └── 批量下载模板.xlsx               # 批量下载模板文件
│   └── ICO/                                # 图标资源目录
│       ├── icon-512x512.png
│       ├── icon.ico
│       └── icon.png
├── docs/                                   # 文档目录
│   ├── development_standard.md             # 开发规范
│   ├── development_guide.md               # 开发指南
│   └── project_status.md                  # 项目现状记录
└── requirements.txt                        # 依赖清单
```

### 1.3 技术栈

- **编程语言**: Python 3.8+
- **浏览器自动化**: Selenium 4.6.0+
- **数据处理**: pandas, openpyxl
- **外部工具**: N_m3u8DL-RE, FFmpeg
- **代码格式化**: Black
- **测试框架**: pytest

### 5.3 智能决策

基于现有项目内容和工程实践,对以下事项进行决策:

#### 5.3.1 文件命名规范

**决策**: 采用简洁的命名规范

- 保持原始文件名,不添加版本号或平台后缀
- 文件名使用小写字母、数字、连字符(-)和下划线(\_)
- 文件名长度不超过 255 个字符
- 不允许空格和特殊字符(如@#$%^&\*等)

**理由**:

- 简化文件管理,降低复杂度
- 避免版本号导致的多文件问题
- 保持与现有项目结构一致
- 符合跨平台兼容性要求

#### 5.3.2 文件类型限制

**决策**: assets/bin 目录仅存放可执行文件

- Windows: .exe 文件
- Linux/macOS: 无扩展名的可执行文件
- 允许必要的依赖文件(.dll, .so 等)
- 不允许配置文件和数据文件

**理由**:

- 明确目录职责,避免混淆
- 便于权限管理和安全控制
- 符合软件工程最佳实践

#### 5.3.3 目录结构说明

**决策**: 在两份文档中添加完整的项目目录结构树状图

- 使用 mermaid 或 ASCII 树状图展示
- 为每个主要目录添加职责说明
- 使用代码块格式展示标准路径
- 使用加粗文本突出显示关键路径

**理由**:

- 提高文档可读性和易用性
- 便于开发者快速了解项目结构
- 符合用户需求中的"通用更新要求"

#### 5.3.4 更新优先级

**决策**: 仅更新 development_standard.md 和 development_guide.md

- 不更新 project_status.md(作为历史记录保留)
- 不更新其他文档(超出任务范围)
- 不更新代码中的路径引用(超出任务范围)

**理由**:

- 严格遵循任务边界
- project_status.md 记录的是项目现状,不应修改
- 代码更新属于另一个任务范围
- 保持任务聚焦,避免范围蔓延
