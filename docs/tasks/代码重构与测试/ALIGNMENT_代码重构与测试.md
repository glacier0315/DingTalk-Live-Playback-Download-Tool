# ALIGNMENT_代码重构与测试

## 一、项目特性规范

### 1.1 项目概述

**项目名称**：钉钉直播回放下载工具（DingTalk-Live-Playback-Download-Tool）

**项目类型**：Python 命令行工具

**核心功能**：从钉钉直播回放分享链接下载视频文件

**技术栈**：
- Python 3.x
- Selenium 4.6.0+（浏览器自动化）
- Pandas（数据处理）
- N_m3u8DL-RE（外部下载工具）
- Tkinter（GUI 文件选择）

**当前架构**：单文件架构，所有代码集中在 `DingTalk-Live-Playback-Download-Tool.py`（约 806 行）

### 1.2 核心功能模块

#### 1.2.1 用户交互模块
- **功能**：处理用户输入和模式选择
- **主要函数**：
  - `validate_input()`：输入验证
  - `single_mode()`：单个视频下载模式
  - `batch_mode()`：批量下载模式
- **输入**：命令行输入（下载模式、保存模式、浏览器类型、链接/文件路径）
- **输出**：用户选择的配置参数

#### 1.2.2 文件读取模块
- **功能**：从 CSV/Excel 文件中提取钉钉直播链接
- **主要函数**：
  - `read_links_file()`：读取链接文件
  - `clean_file_path()`：清理文件路径
- **输入**：文件路径（CSV/Excel）
- **输出**：链接字典 `{index: url}`

#### 1.2.3 浏览器自动化模块
- **功能**：通过 Selenium 控制浏览器获取 Cookie 和请求头
- **主要函数**：
  - `get_browser_cookie()`：首次获取 Cookie
  - `repeat_get_browser_cookie()`：重复获取 Cookie
- **支持浏览器**：Edge、Chrome、Firefox
- **输入**：钉钉链接、浏览器类型
- **输出**：浏览器实例、Cookie 字典、请求头字典、直播名称

#### 1.2.4 m3u8 链接提取模块
- **功能**：从浏览器网络日志中提取 m3u8 视频流链接
- **主要函数**：
  - `fetch_m3u8_links()`：提取 m3u8 链接
  - `refresh_page_by_click()`：刷新页面
  - `extract_prefix()`：提取基础 URL
- **输入**：浏览器实例、浏览器类型、钉钉链接
- **输出**：m3u8 链接列表

#### 1.2.5 视频下载模块
- **功能**：调用 N_m3u8DL-RE 工具下载视频
- **主要函数**：
  - `download_m3u8_file()`：下载 m3u8 文件
  - `download_m3u8_with_options()`：手动选择路径下载
  - `download_m3u8_with_reused_path()`：复用路径下载
  - `auto_download_m3u8_with_options()`：默认路径下载
- **输入**：m3u8 文件、保存名称、基础 URL、Cookie、请求头
- **输出**：下载的视频文件

#### 1.2.6 二进制程序调用模块
- **功能**：根据操作系统选择可执行文件
- **主要函数**：
  - `get_executable_name()`：获取可执行文件名
- **输入**：无
- **输出**：可执行文件名（Windows/Linux/macOS）

### 1.3 外部依赖

#### Python 依赖
- `selenium>=4.6.0`
- `pandas`
- `openpyxl`
- `xlrd`
- `tkintertable`

#### 外部二进制工具

#### 4.1.2 代码质量问题

**1. 单文件架构**
- 所有代码集中在 806 行的 Python 文件中
- 缺乏模块化设计，代码可维护性差
- 功能耦合度高，难以独立测试和扩展

**2. 代码重复**
- 三个下载函数（`download_m3u8_with_options`、`download_m3u8_with_reused_path`、`auto_download_m3u8_with_options`）存在大量重复代码
- Cookie 和请求头添加逻辑重复
- 命令构建逻辑重复

**3. 命名不规范**
- 全局变量 `browser` 使用不规范
- 部分变量名不够描述性（如 `a`、`b` 等）
- 函数名不够统一

**4. 缺少注释和文档**
- 代码注释较少
- 缺少函数文档字符串
- 缺少模块文档

**5. 错误处理不完善**
- 部分异常处理过于简单，仅打印错误信息
- 缺少详细的错误日志记录
- 异常情况下直接退出程序

**6. 缺少单元测试**
- 无任何测试代码
- 无法验证功能正确性
- 重构风险高

**7. 硬编码问题**
- XPath 和 CSS 选择器硬编码在代码中
- 默认请求头硬编码
- 文件名和路径硬编码（如 `output.m3u8`）

#### 4.1.3 核心功能分析

**1. 用户交互**
- 支持两种模式：单个下载、批量下载
- 支持两种保存模式：默认路径、手动选择
- 支持三种浏览器：Edge、Chrome、Firefox

**2. 文件读取**
- 支持 CSV 和 Excel 文件
- 支持多种编码（utf-8、gbk）
- 自动遍历所有单元格提取链接

**3. 浏览器自动化**
- 使用 Selenium 控制浏览器
- 获取 Cookie 和请求头
- 获取直播视频名称

**4. m3u8 链接提取**
- 从浏览器网络日志中提取
- 支持三种浏览器的不同日志格式
- 重试机制（5 次）

**5. 视频下载**
- 调用 N_m3u8DL-RE 工具
- 添加 Cookie 和请求头
- 支持自定义保存路径

### 4.2 重构目标

#### 4.2.1 模块化重构

**目标**：将单文件拆分为多个模块，提高代码可维护性

**策略**：
- 按功能领域划分模块
- 每个模块职责单一
- 降低模块间耦合度

**模块划分**：
1. `core/downloader.py`：下载器核心逻辑
2. `core/cookie_handler.py`：Cookie 处理逻辑
3. `core/m3u8_parser.py`：m3u8 解析逻辑
4. `utils/file_reader.py`：文件读取工具
5. `utils/validator.py`：输入验证工具
6. `utils/path_helper.py`：路径处理工具
7. `binary/n_m3u8dl_re.py`：N_m3u8DL-RE 调用封装
8. `binary/ffmpeg_wrapper.py`：FFmpeg 调用封装
9. `browser/browser_factory.py`：浏览器工厂
10. `browser/edge_driver.py`：Edge 浏览器驱动
11. `browser/chrome_driver.py`：Chrome 浏览器驱动
12. `browser/firefox_driver.py`：Firefox 浏览器驱动
13. `config/settings.py`：配置项定义
14. `config/constants.py`：常量定义

#### 4.2.2 消除代码重复

**目标**：消除重复代码，提高代码复用性

**策略**：
- 提取公共逻辑到独立函数
- 使用工厂模式创建浏览器实例
- 统一下载命令构建逻辑

**具体措施**：
1. 合并三个下载函数为一个通用下载函数
