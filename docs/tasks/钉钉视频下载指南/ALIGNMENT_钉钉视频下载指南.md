## 需求理解

### 钉钉视频下载流程分析

基于现有文档和代码分析,钉钉视频下载的完整流程如下:

1. **链接输入**: 用户输入钉钉直播回放链接

   - 格式示例: `https://n.dingtalk.com/dingding/live-room/index.html?roomId=JC0D5jhMaB&liveUuid=9f3171a7-3b52-47ca-917a-bcc2f02e33f5`
   - 关键参数: `roomId`, `liveUuid`

2. **浏览器自动化**: 使用 Selenium 启动浏览器

   - 支持 Edge、Chrome、Firefox
   - 自动导航到钉钉页面
   - 等待用户手动登录

3. **Cookie 获取**: 从浏览器中提取登录 Cookie

   - Cookie 包含: `account`, `deviceid`, `pub_uid`, `LV_PC_SESSION`, `lv_token`, `isg`
   - 这些 Cookie 是访问钉钉视频流的必要凭证

4. **M3U8 解析**: 从网络日志中提取 M3U8 视频流地址

   - M3U8 地址格式: `https://dtliving-sz.dingtalk.com/live/{liveUuid}_normal.m3u8?auth_key=...`
   - auth_key 包含时间戳和签名,用于鉴权

5. **视频下载**: 使用 N_m3u8DL-RE 下载视频片段

   - 下载 M3U8 文件中列出的所有.ts 视频片段
   - 每个片段都有独立的 auth_key 参数

6. **视频合并**: 使用 FFmpeg 合并视频片段
   - 将下载的.ts 片段合并为完整的视频文件
   - 输出格式: MP4

### 钉钉鉴权机制分析

基于文档分析,钉钉平台的鉴权机制包括:

1. **Cookie 鉴权**:

   - 用户登录后,浏览器会保存多个 Cookie
   - 这些 Cookie 在请求 M3U8 文件和视频片段时必须携带
   - 主要 Cookie: `account`, `lv_token`, `deviceid`

2. **auth_key 鉴权**:

   - M3U8 文件和视频片段 URL 都包含`auth_key`参数
   - auth_key 格式: `{timestamp}-{signature}-{0}-{md5}`
   - timestamp: Unix 时间戳
   - signature: 签名(基于时间戳和密钥生成)
   - md5: MD5 哈希值

3. **Referer 验证**:

   - 请求必须携带正确的 Referer 头
   - Referer: `https://n.dingtalk.com/`

4. **User-Agent 验证**:
   - 请求必须携带合法的 User-Agent 头
   - 模拟真实浏览器访问
